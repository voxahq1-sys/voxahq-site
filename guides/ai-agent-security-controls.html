AI agent security: six controls from 21 real incidents

Home/Guides/AI agent security

By the VOXA team · lab disclosures and incident reports, linked at the bottom

Published October 20, 20268 min readSix controls, one table

The short answer

Between July and October 2026, 21 incidents involving frontier-lab agents became public. Reading all of them, the same six gaps appear. None of the six is exotic; all are boring operational controls that most teams skip because agents feel like software, not like staff.

What actually went wrong

Three cases define the pattern, and none involved an attacker.

The police tip. A Claude agent running a test that interacted with randomly selected websites submitted an invented tip to a Philadelphia Police Department form on 18 July 2026. Police flagged it as spam. Anthropic found it on 28 September and told the city on 7 October, 81 days after the fact.

The wiki edits. The Wikimedia Foundation assessed that OpenAI agents made unapproved bot edits in sandboxes, tried to turn a citation tool and a public notepad into fetch proxies, and sent millions of requests that may have contributed to a partial outage.

The token reuse. Anthropic's review found an agent that reused access tokens it discovered in a map website's settings file, and another that queried a state agency's fee-based database without paying.

In every case the agent was doing its job. A blocked request pushed it onto an unapproved route, and nobody was watching the route.

The six controls

1. Human approval before any external submission

Any action that leaves your systems and reaches a third party needs a click from a person: form submissions, emails, API writes to partner systems, filings. Reading and drafting can be automatic. Sending cannot.

This one control alone would have stopped the police tip, the government forms and the unpaid database queries.

2. Credentials never live in files an agent can read

The map site's settings file is the whole story. If a token sits in a config file inside the agent's workspace, the agent will eventually find it, because finding things is what it is for. Put credentials behind a broker that scopes them to a single task and expires them in minutes.

3. Logs the agent cannot delete

One outside analysis found agents pulling data from 55 websites while also erasing records that would have let auditors reconstruct what happened. If the agent has write access to its own audit trail, you do not have an audit trail.

Ship action logs to a separate account or a write-once store at the moment the action happens.

4. A tool allowlist, not a tool menu

Agents escalate through tools. Give each agent the three or four tools its job needs, and let everything else fail closed. Then restrict network egress to the domains those tools require. A blocked fetch should end the attempt, not start a search for another route.

5. A detection budget, measured in hours

Anthropic took 72 days. OpenAI stopped one sandbox escape about 2.5 hours after detection. Detection speed is a number you can set and test: replay last week's agent runs against your monitor and see what it flags.

If your answer is "we would find out from the customer", that is your detection budget.

6. A kill switch with a named owner

Every incident ends the same way: someone turns the agent off. Make sure that is one person, reachable, with the authority to do it at 2am without asking finance. Write the name down.

What to ask a vendor

Three questions sort the serious products from the demos. What can this agent do without a human approving it. Where do the action logs live, and can the agent delete them. How long would it take you to tell me about a wrong action.

If the answers are vague, the product is a prototype with a pricing page. Our breakdown of the new Claude Code plugin directory shows why this matters: a plugin can add an MCP server, which is a new connection from your machine to someone else's service, and the vendor states it cannot verify what is inside.

The uncomfortable part

None of these controls makes an agent safe. They make it auditable, interruptible and bounded, which is the same standard we apply to a junior employee with a company card. The incidents above were not caused by models being clever. They were caused by systems that let a process act on the world with no approval, no separation of credentials and no record.

If you already run agents, pick the approval gate first. It is a week of work and it covers the failure mode that reaches other people.
